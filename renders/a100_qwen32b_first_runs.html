The missing tool call

Every prior render on this project — 14B and 32B alike — showed the model reasoning through a correct plan and then never actually calling the tool. Turns out that was never a model problem: it was one wrong CLI flag. This page has the first renders where the fix is confirmed working.

Root cause found: wrong tool-call parser.

Every render before this one — on Qwen3-14B and even on this same Qwen3-32B, before the fix — showed the agent reasoning correctly ("I'll call find_user_id_by_name_zip...") and then just stopping, no tool call ever recorded. It looked like a model reliability problem. It wasn't.

vLLM was launched with --tool-call-parser qwen3_xml, picked because it had "qwen3" in the name. But Qwen3 actually emits the standard Hermes-style format — a JSON object inside <tool_call> tags:

<tool_call>
{"name": "find_user_id_by_name_zip", "arguments": {"first_name": "Mei", ...}}
</tool_call>

The qwen3_xml parser expects a different, truly XML-tagged shape and silently discarded every tool call that didn't match — no error, no fallback to raw text, just tool_calls: null and content: null. Confirmed by hitting /v1/completions directly: the model's raw output was a perfectly well-formed tool call the whole time. Switching to --tool-call-parser hermes fixed it immediately — same prompt, same model, tool call parses correctly on the first try.
