First real eval results off the RunPod GPU pod: Qwen3-14B-AWQ served through actual vLLM (not the old DIY transformers hack), with gpt-4o playing the customer. Two randomly-picked test tasks — retail task 9 and airline task 8. Retail 9 is the interesting one: the agent's action sequence matches the ground truth exactly, call for call, argument for argument — and it's still graded a fail.

Why this setup is different from earlier renders.

Every prior render on this project ran on a local 8GB GTX 1080 (Pascal, no flash-attention support), which is what forced the tiny 0.6B/8B models and the custom quantized transformers server. This one runs on a rented RunPod pod (RTX 2000 Ada, 16GB, real flash-attention via FlashInfer) serving Qwen3-14B-AWQ through actual vLLM with native tool-call parsing (qwen3_xml). Full story of getting there — SSH gateway quirks, a KV-cache sizing crash, an expired API key saga — is in tau-train/what_ive_done.md.

Retail task 9: a perfect action match, still scored a fail.

The agent called find_user_id_by_name_zip → get_user_details → get_order_details → get_product_details ×2 → exchange_delivered_order_items — the exact same six calls, same arguments, same order as the task's own ground truth. τ-bench still returned reward: 0.0. This lines up with the warning already noted in tau-train/what_ive_done.md: this repo's own README flags its retail/airline task definitions as outdated, superseded by τ³-bench. Worth treating any single-task "fail" from this repo with a grain of salt until that migration happens.
